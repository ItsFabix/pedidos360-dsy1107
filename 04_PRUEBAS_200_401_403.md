# 04 — Pruebas 200 / 401 / 403

## 1. 200 — solicitud autorizada

Condiciones:

- usuario autenticado en Angular;
- Access Token destinado a la API;
- `aud` = Client ID API;
- `scp` contiene `Pedidos.Read`;
- API Gateway JWT Authorizer correcto;
- Spring Security correcto.

Desde Angular → **Consultar pedidos**.

Esperado:

```text
200 OK
```

## 2. 401 — sin autenticación válida

```bash
curl -i https://<api-id>.execute-api.us-east-1.amazonaws.com/api/pedidos
```

Sin `Authorization: Bearer`:

```text
401 Unauthorized
```

## 3. 403 — token válido sin scope suficiente

Forma controlada para la demostración de Semana 05:

1. Crear temporalmente en API Gateway una ruta `GET /api/pedidos-escritura`.
2. Asociarla a `integ-pedidos`.
3. Asociar `entra-jwt-authorizer`.
4. Authorization scope: `Pedidos.Write`.
5. Utilizar un token que contenga solo `Pedidos.Read`.
6. Esperado:

```text
403 Forbidden
```

7. Eliminar la ruta temporal al terminar la evidencia.

## 4. 403 por role Admin — backend

El proyecto incluye:

```text
GET /api/admin/resumen
```

Spring Security exige:

```text
ROLE_Admin
```

Un usuario autenticado sin el App Role `Admin` debería ser rechazado por el backend.

> Esta prueba de role es complementaria. La prueba obligatoria principal de autorización de API Gateway usa scopes.
